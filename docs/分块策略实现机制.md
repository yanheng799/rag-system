# 分块策略实现机制

本文档详细分析 RAG 系统中各类文件的分块策略实现机制，涵盖解析、分组、组装的完整流程。

## 1. 核心数据模型

`src/models/chunks.py` 定义了三个关键数据结构：

| 结构 | 作用 |
|------|------|
| `ContentElement` | 单个内容片段，`type` 可为 `text`/`table`/`image`，表格元素可附带 `image_url`（截图） |
| `ChunkMetadata` | 分块元数据，`chunk_id` 格式为 `{doc_id}_p{page}_c{index}`，`group_id` 标识是否由同一段落拆分而来 |
| `MixedChunk` | 最终分块产物——可包含交错排列的文本、表格、图片元素，`full_text` 用于向量化 |

所有解析器输出的中间表示为 `ParsedElement`（`src/ingestion/parsers/base.py`），包含以下字段：

- `elem_type`：`text`/`table`/`title`/`list_item`/`image`
- `content`：文本内容
- `page`：页码（Excel 中为工作表索引）
- `bbox`：`(x0, y0, x1, y1)` 坐标，非 PDF 格式使用 `(0, 0, 0, 0)`
- `style`：字体大小、粗体、标题级别、工作表名等样式信息
- `raw`：原始数据（如 pymupdf 表格对象，或 `{"headers": [...], "rows": [...]}`）

## 2. 六种文件解析器

每种文件类型有独立的解析策略，产出统一的 `ParsedElement` 列表。解析器通过 `ParserRegistry`（`src/ingestion/parsers/registry.py`）按文件扩展名分发。

### 2.1 PDF 解析器（`pdf_parser.py`）

基于 pymupdf，是所有解析器中最复杂的一个。

**预处理**：

- **页眉页脚检测**（`detect_header_footer_zones()`）：扫描页面顶部 8% 和底部 10% 区域，统计多页中相同 y 坐标重复出现的文本行，识别为页眉/页脚
- **目录页跳过**（`detect_toc_pages()`）：扫描前 20% 页面（最多 20 页），识别以点引导线（`...........`）为主的页面，跳过不参与分块

**逐页提取**（`_parse_page()`）：

1. 优先提取表格（`page.find_tables()`），转为 Markdown 格式，过滤无效表格（空单元格过多）
2. 提取文本块，排除与表格区域重叠、页眉页脚区域、页码的内容
3. 按字体大小比例（以页面正文字号的众数为基准）、粗体检测、正则标题模式，将行分类为 `title`、`list_item` 或 `text`
4. 相邻同类型行合并为单个 `ParsedElement`

**图片提取**（`_extract_images()`）：

过滤规则：
- 最小尺寸 ≥ 50px
- 面积占比 ≥ 页面面积的 0.5%
- 与表格重叠面积 < 50%

**后处理**：

| 后处理步骤 | 函数 | 逻辑 |
|-----------|------|------|
| 跨页表格合并 | `merge_cross_page_tables()` | 相邻页面上，表 A 底部 > 85% 页高、表 B 顶部 < 15% 页高、列数匹配 → 合并 |
| 跨栏表格合并 | `merge_cross_column_tables()` | 同一页面上，表格分列中线两侧、y 坐标相近、列数匹配 → 合并 |
| 双栏布局重排 | `reorder_elements_for_layout()` | 检测双栏页面后，按左栏从上到下、右栏从上到下的阅读顺序重排元素 |

### 2.2 Word 解析器（`word_parser.py`）

基于 python-docx，直接遍历文档 XML 子节点：

- **段落**（`<p>` 标签）：按样式名识别标题（`Heading 1`）、目录（`toc 1`）、列表（`List Paragraph`）。目录条目跳过，嵌入图片单独提取为 image 元素
- **表格**（`<tbl>` 标签）：转为 Markdown 表格
- 页码统一为 `page=1`，bbox 为 `(0, position, 0, position+1)`（position 为单调递增计数器），走零坐标的段落分组降级路径

### 2.3 Excel 解析器（`excel_parser.py`）

基于 openpyxl，每个工作表视为一个"页面"：

- 首行非空行作为表头
- 数据行按每 100 行（`MAX_ROWS_PER_ELEMENT`）分为一组
- 每组生成 `elem_type="table"` 的 `ParsedElement`，`raw` 中保留 `{"headers": [...], "rows": [...]}`
- 内容通过 `format_rows()` 转为自然语言格式（`列A: 值; 列B: 值`）
- 合并单元格在 `style` 中标记

### 2.4 CSV 解析器（`csv_parser.py`）

- 自动检测分隔符：先尝试 `csv.Sniffer`，失败后依次尝试 `,`、`;`、`\t`，选择列数最稳定的
- 自动识别表头行（`csv.Sniffer().has_header()`）
- 与 Excel 类似的 100 行分组 + `format_rows()` 格式化
- 所有元素 `bbox=(0, 0, 0, 0)`，`page=1`

### 2.5 TXT 解析器（`txt_parser.py`）

- 按双换行（`\n\n`）分段，每段生成 `elem_type="text"` 的 `ParsedElement`
- 带 `style={"paragraph_break": True}` 标记，供段落分组使用
- 超过 8192 字符（`MAX_ELEMENT_SIZE`）的段落按行拆分，仍超限则硬截断

### 2.6 Markdown 解析器（`markdown_parser.py`）

状态机解析器，跟踪 `in_code_block`、`in_table`、`text_buffer` 三个状态：

| Markdown 语法 | 产出 elem_type | style 标记 |
|---------------|---------------|-----------|
| `# 标题` | `title` | `{"heading_level": N}` |
| 围栏代码块 | `text` | `{"code_block": True}` |
| Markdown 表格 | `table` | — |
| 列表项 | `list_item` | — |
| 普通段落 | `text` | — |

行内格式（粗体、斜体、链接、图片引用、删除线）被剥离。空行触发文本缓冲区刷新，产生段落边界。

## 3. 五种分块策略

分块策略位于 `src/ingestion/chunkers/strategies/`，通过 `ChunkerRegistry` 按名称分发：

### 3.1 策略总览

| 策略名称 | 分组依据 | 适用场景 | 源文件 |
|---------|---------|---------|-------|
| `paragraph`（默认） | 段落边界检测（坐标 + 语义） | 通用文档 | `paragraph_chunker.py` |
| `heading` | 仅在标题处切分 | 以章节为单位的结构化文档 | `heading_chunker.py` |
| `page` | 按页码分组 | 页内容独立的文档 | `page_chunker.py` |
| `fixed_size` | 滑动窗口（字符数）+ 可选重叠 | 无结构文档 | `fixed_size_chunker.py` |
| `qa` | 表格每行一个分块 | FAQ / 知识库表格 | `qa_chunker.py` |

### 3.2 段落分块策略（ParagraphChunker）—— 默认策略

核心逻辑在 `src/ingestion/chunkers/paragraph_grouper.py`，分两个阶段：

#### 阶段一：段落边界检测

`is_new_paragraph_boundary()` 按优先级依次检查 6 条规则：

| 优先级 | 规则 | 说明 |
|-------|------|------|
| ① | 空组 | 当前分组为空 → 新段落 |
| ② | 章节标题 | 当前元素为严格章节标题（`is_section_heading` 或文档级标题）→ 始终新段落 |
| ③ | 跨页连续 | 前一元素在页尾（> 85% 页高）+ 当前元素在页首（< 15% 页高）→ **不切分**（延续同一自然段）；若当前分组以章节标题开头，放宽至页面前 40% |
| ④ | 垂直间距 | 当前元素与前一个元素的垂直间距 > 阈值 → 新段落；但如果前一元素是标题则例外（标题吸收后续内容） |
| ⑤ | 首行缩进 | 当前元素 x0 明显大于正文左边距 → 新段落 |
| ⑥ | 段末短行 | 前一元素 x1 明显小于正文右边距 → 前一行为段落结尾，当前元素开始新段落 |

**自适应特性**：

- **主导行间距检测**（`_detect_dominant_line_spacing()`）：计算同页文本元素间垂直间距的众数，若众数超过默认阈值（15px），自动提高阈值
- **正文边距检测**（`_detect_page_body_margins()`）：按 x0 聚类元素检测栏数，计算每栏的左右边距众数，支持双栏布局
- **零坐标降级**（`is_new_paragraph_boundary_fallback()`）：当所有元素 `bbox=(0, 0, 0, 0)`（TXT/MD/CSV/Excel/Word）时，改用标题级别、`paragraph_break` 标记等非空间信号

#### 阶段二：后处理

| 步骤 | 函数 | 说明 |
|------|------|------|
| 孤立标题合并 | `_merge_heading_only_groups()` | 仅含标题（总字符 < 40）的分组 → 合并到下一组 |
| 过大分组拆分 | `split_oversized_groups()` | 超过 `max_chunk_size` 的组按元素拆分；保护标题不被孤立、表格说明文字（< 30 字符）不与表格分离；拆分后的子组共享同一 `group_id` |
| 过小分块合并 | `merge_small_chunks()` | 低于 `min_chunk_size`（默认 50 字符）的组与相邻组合并 |

### 3.3 标题分块策略（HeadingChunker）

- 仅在标题边界切分（`is_title`、`is_section_heading` 或 `is_heading_by_pattern`）
- 每个标题及其后续所有非标题元素形成一个分组，直到下一个标题
- 之后应用过大分组拆分和过小分块合并

### 3.4 按页分块策略（PageChunker）

- 按页码分组，每页一个分组
- 之后应用过大分组拆分和过小分块合并
- 简单但粒度较粗

### 3.5 固定大小分块策略（FixedSizeChunker）

- 纯字符计数的滑动窗口，支持 `overlap`（从上一个窗口末尾携带的字符数）
- 单个元素超过 `max_chunk_size` 时，通过 `_split_element()` 进行字符级拆分
- 尾部过小分块合并到前一组

### 3.6 QA 分块策略（QaChunker）

- 专为结构化表格数据设计（FAQ / 知识库场景）
- 表格元素（具有 `raw["headers"]` 和 `raw["rows"]`）：每一行生成独立分块，通过 `format_rows()` 格式化
- 非表格元素：每个元素独立成块
- 不进行大小拆分

## 4. 标题检测机制

`src/ingestion/chunkers/heading_patterns.py` 提供多级标题检测：

| 函数 | 匹配范围 | 最大长度 | 用途 |
|------|---------|---------|------|
| `is_heading_by_pattern(text)` | 中文章/节/条/款编号（`第X章`）、数字编号标题（`3.2 ...`）、英文 Chapter/Section/Part | 100 字符 | 宽匹配，用于标题分块策略 |
| `is_section_heading(text)` | 仅严格章节级编号（`1.3.1`、`第X章`），排除纯列表项（`1、`） | 60 字符 | 严格匹配，用于段落边界决策 |
| `is_heading_combined(text, font_size, is_bold)` | 结合样式（字号 ≥ 14pt，或粗体且字号 ≥ 12pt）+ 正则 | — | 综合判断 |

## 5. 分块组装

`src/ingestion/chunkers/chunk_assembler.py` 中的 `ChunkBuilder` 将元素组转为最终的 `MixedChunk`：

| 元素类型 | 处理方式 |
|---------|---------|
| **文本** | 直接创建 `ContentElement(type="text", content=...)` |
| **表格** | 调用 `TableDescriber.describe()` 获取内容描述 + `TableScreenshot` 截取表格区域图片并上传 OSS → `ContentElement(type="table", image_url=...)` |
| **图片** | 从 `raw["oss_path"]` 读取已上传路径 → `ContentElement(type="image")` |

所有元素内容按换行拼接为 `full_text`（用于向量化）。

元数据构建：
- `chunk_id`：`{doc_id}_p{page}_c{chunk_index}`
- `chunk_type`：`text`/`table`/`mixed`/`image`（由 `detect_chunk_type()` 根据元素类型分布判定）
- `pages`：分块跨越的所有页码列表（支持跨页合并表格）
- `group_id`：来自分块器输出，标识同源拆分

## 6. 表格处理

表格在整条流水线中享有特殊处理：

### 6.1 表格描述（`src/ingestion/table_processor/describer.py`）

- 当前为 Phase 1 实现：直接透传解析器已生成的 Markdown 表格内容
- 预留 LLM 表格描述能力（Qwen-VL），后续阶段接入

### 6.2 表格截图（`src/ingestion/table_processor/screenshot.py`）

- PDF：以 150 DPI 渲染页面，按 bbox 裁剪表格区域（5px 内边距），上传 OSS
- 跨页合并表格：为每个合并延续页单独截图
- Word：先通过 LibreOffice 转为 PDF，再渲染（无精确 bbox）

### 6.3 图片提取（`src/ingestion/table_processor/image_extractor.py`）

- 从 PDF/Word 中提取嵌入图片并上传 OSS
- 过滤规则与 PDF 解析器一致（最小尺寸、面积占比、表格重叠）

## 7. 布局分析

`src/ingestion/chunkers/layout_detector.py` 提供 PDF 专用的布局分析能力：

| 功能 | 函数 | 算法 |
|------|------|------|
| 页眉页脚检测 | `detect_header_footer_zones()` | 顶部 8% / 底部 10% 区域，多页相同 y 坐标出现 ≥ 3 次的文本行 |
| 单双栏检测 | `detect_page_layout()` | 中线处词频分布 + 直方图空隙分析（≥ 3 个空 bin = 栏分隔） |
| 目录页检测 | `detect_toc_pages()` | 前 20% 页面中，含 ≥ 5 行或 ≥ 40% 的点引导线 |
| 双栏重排序 | `reorder_elements_for_layout()` | 左栏从上到下 → 右栏从上到下，全宽元素按 y 位置穿插 |

## 8. 流水线编排

`src/ingestion/pipeline.py` 中的 `IngestionPipeline.ingest()` 编排完整流程：

```
文件上传
  │
  ├─ 1. 状态更新 → "processing"
  ├─ 2. OSS 上传原始文件
  ├─ 3. ParserRegistry 分发 → 解析器产出 list[ParsedElement]
  │       └─ [PDF 后处理: 跨页表格合并、跨栏表格合并、双栏重排]
  ├─ 4. ChunkerRegistry 分发 → 分块策略产出 list[(element_group, group_id)]
  │       配置项: strategy / max_size / min_size / overlap / vertical_gap
  ├─ 5. 图片上传 → 未上传的 image 元素上传至 MinIO
  ├─ 6. ChunkBuilder → MixedChunk（含表格截图 + 图片 URL）
  ├─ 7. Embedder → 向量化（text-embedding-v2, 1024 维）
  ├─ 8. Milvus 写入（向量 + 元数据）
  ├─ 9. PostgreSQL 写入（ChunkRecord）
  └─ 10. 状态更新 → "done" / "failed"
```

## 9. 关键设计决策

| 决策 | 说明 |
|------|------|
| **空间文档 vs 非空间文档** | PDF 使用坐标驱动的段落检测；TXT/MD/CSV/Excel/Word 使用标记/样式驱动的降级路径 |
| **MixedChunk 混合内容** | 单个分块可包含交错排列的文本和表格元素；`full_text` 用于向量化，`image_url` 存储表格截图但不进入 LLM prompt |
| **group_id 机制** | 标识因大小限制被拆分的同源段落，供下游理解分块间的关联性 |
| **表格全程特殊处理** | 独立解析 → 跨页/跨栏合并 → 语义描述 + 视觉截图 → 分块类型判定 |
| **解析器插件注册表** | `BaseParser` 实现按文件类型注册，`ParserRegistry` 按扩展名分发，便于扩展新格式 |
| **增量 Milvus 更新** | 新文档添加时无需重建整个向量索引 |
